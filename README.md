# 图片加密解密工具

## 软件介绍

图片加密解密工具是一款运行于 Windows 的桌面小程序，用于把本机的图片
处理成**无法直接观看**的形式，再凭加密时生成的密钥文件还原回来。

需要说明的是：本工具做的是**像素置乱**，属于「防随手翻看」级别的
内容遮蔽，**不是密码学意义上的加密**。它不适合用来保护高价值或高度敏感的
数据——如果你需要对抗有意的破解，请使用专业的加密软件（如 VeraCrypt、7-Zip
的 AES-256 加密）。

## 实现原理（如实说明）

把图片的像素矩阵展开成一维序列，用 `numpy.random.shuffle` 生成一个随机下标
序列，按这个序列重新排列像素，再存成 PNG。

像素颜色值一个都没改，只是位置被打乱了，所以**解密是无损的**。
密钥文件（`.key`）里保存的就是这张置换表，外加原始颜色模式和原始扩展名。

> **关于强度**：密钥是随加密文件一同保存的置换表，不构成密码学保护，
> 请在了解这一点的前提下使用。

## 支持格式

- **图片输入**：JPG、JPEG、PNG、BMP、GIF
- **加密输出**：PNG（无损，任何看图软件都能打开，只是画面为噪点）
- **解密输出**：按原始扩展名与原始颜色模式还原
- **密钥**：`.key` 文件，加密时自动生成

## 使用方法

### 加密操作

1. 打开软件
2. 点击「浏览」选择要加密的图片
3. 确认操作类型为「加密」
4. 点击「执行操作」
5. 完成后会生成加密图片和对应的密钥文件

### 解密操作

1. 打开软件
2. 点击「浏览」选择要解密的加密图片
3. 选择操作类型为「解密」，此时界面会多出一行「密钥路径」
4. 点击「浏览」选择加密时生成的同名 `.key` 密钥文件
5. 点击「执行操作」
6. 完成后会生成还原后的图片

## 功能特性

- **像素置乱**：见上文「实现原理」，请注意其强度边界
- **无损还原**：只改变像素位置，解密结果与原始图片逐像素一致
- **进度显示**：实时显示处理进度
- **操作取消**：处理过程中可随时点击「取消」中止任务
- **硬件加速自适应**：自动检测 OpenCL / UMat，可用时在显卡上运算
- **单文件处理**：每次处理一张图片；加密结果的文件名带时间戳，多次处理不会互相覆盖
- **绿色免安装**：不写注册表、不向系统目录安装文件，复制文件夹即可迁移

## 运行环境

- **操作系统**：Windows 10 / 11（64 位）
- **Python 版本**：3.8 及以上（源码方式运行时需要）
- **依赖库**：
  - NumPy 2.0 及以上
  - OpenCV（opencv_python）
  - Pillow
- **无需任何外部程序**：不依赖 FFmpeg 等第三方可执行文件

安装依赖：

```bash
pip install -r requirements.txt
```

启动：

```bash
python src/main.py
```

## 打包成 exe

打包参数全部固化在 `.spec` 里（无控制台窗口、禁用 UPX 压缩、显式声明隐藏导入），
因此换一台机器也能得到一致的结果。用打包脚本调用：

```bash
python build_exe.py            # 单文件版，产物输出到 dist/
python build_exe.py --onedir   # 目录版，产物输出到 dist_onedir/<名称>/
python build_exe.py --smoke    # 打包后顺便启动一次，确认主窗口能出现
python build_exe.py --dry-run  # 只做环境自检，不执行打包
```

**单文件版（onefile）与目录版（onedir）怎么选：**

| | 单文件版 `dist/` | 目录版 `dist_onedir/` |
| --- | --- | --- |
| 分发 | 就一个 exe，方便 | 必须整个文件夹一起发 |
| 启动 | 每次运行都要把 60+ MB 解包到系统临时目录，首次约 3 秒 | 不解包，立刻启动 |
| 抗环境问题 | 临时目录不可写、被杀软拦截、或 exe 所在文件夹带异常 ACL 时，会弹 `Could not create temporary directory!` 并退出 | 不受上述问题影响 |

> 如果双击单文件版出现 `Could not create temporary directory!`，说明它所在位置的环境
> 不允许创建临时目录：把 exe 换到别的文件夹（例如桌面）再试，或者改用目录版。

打包前会自检 Python 版本、7 个源码文件、以及 PyInstaller / NumPy / OpenCV /
Pillow / tkinter 是否齐全；旧的同名产物会先自动备份到 `_previous/<时间戳>/`，
不会被直接覆盖。

打完包建议再跑一次验收脚本：

```bash
python verify_exe.py
```

它会真实启动 exe、通过界面各完成一次加密与解密，并逐像素比对还原结果是否与
原图完全一致，同时确认产物保存在 exe 同目录的 `媒体\` 下。

## 注意事项

1. **密钥保存**：密钥文件是还原的唯一凭据，软件不保存副本、不提供找回功能。
   丢失密钥即等于丢失原始文件，请务必单独备份。
2. **成对保管**：加密文件与密钥文件必须一一对应。文件名中的「_密钥」是识别依据，
   不要改名，也不要用文本编辑器打开。
3. **不要重复加密**：同一张图片连续加密两次，第二次会覆盖第一次的密钥文件
   （密钥文件名不含时间戳），使先前的加密图片无法再还原。
   加密后请立即做一次解密验证。
4. **文件备份**：加密前请保留原始文件，先用解密功能验证一次密钥可用，
   再决定是否删除原文件。
5. **磁盘空间**：加密结果为无损 PNG，通常比原始 JPG 更大，
   建议预留原始文件两倍以上的空间。
6. **不要二次编码**：加密后的图片不要用其他软件重新保存、压缩或转格式，
   任何重新编码都会改变像素值，导致无法还原。
7. **兼容性**：部分特殊编码的图片可能无法正常处理。
